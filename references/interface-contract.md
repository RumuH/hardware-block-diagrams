# Hardware input and agent-authored layout v1

Public hardware input (JSON, optionally YAML): `version:1`, `title`, `view` (`composition` or `microarchitecture`), `modules` (flat array), `connections` (array). Module: `id`, `label`, optional `parent`, `kind`, `count` (positive integer, display aggregation only), `shared_with` (module IDs), `ports` (array of `{id,direction:in|out|inout,width?:integer,protocol?:string}`), `clock_domain`, `description`. Connection: `id`, `source`/`target` (module ID or module.port), `kind:data|control|bus|feedback|clock|reset`, optional `label`, `width`, `protocol`, `bidirectional`. Unknown widths are omitted. Explicit parents define containment; shared_with never implies containment or creates a connection. Connections to a count>1 module apply to the aggregate, no hidden expansion.

Agent-authored layout is separate JSON: `version:1`, `canvas:{width,height}`, `nodes:{moduleID:{x,y,w,h,label_position?:top|center|bottom}}` (absolute geometry), `edges:{connectionID:{source_side:left|right|top|bottom,target_side:...,source_pos?:0..1,target_pos?:0..1,points?:[[x,y]],label_at?:[x,y],wide?:boolean}}`. All nodes and edges must appear; all bends explicit. Node rects for children must be within parent rect. Edge endpoint geometry is calculated from side/fraction and bound to native draw.io modules, including nested parent-relative coordinate conversion. Adjacent repeat instances are real separate modules when individually connected. No graph auto-layout is required: Codex authors deliberate geometric composition from semantic hardware plus references, then deterministic helpers validate and render it. End users do not supply coordinates. Existing coordinates and attachment sides are not locked unless the user says so: redesign placement before routing congested diagrams. See [placement.md](placement.md) for topology-preserving candidate comparison.

Style JSON payload: `version:1`, `name`, `view`, `tokens:{background,font_family,font_size,text_color,border_color,colors:{kind:fill},edge_colors:{kind:color},edge_width,wide_width,corner_radius}`, `rules` (nonempty array of strings), `sample_ids` (array). Colors are six-digit hex; sizes positive finite numbers; corner_radius may be zero. Renderer uses fallbacks for omitted tokens. A style is data, never code. Built-in profiles are in assets/styles; personal profiles are resolved by library.py. Use `--style-revision N` with the actual library revision when rendering a resolved personal profile.

CLI `python3 scripts/diagram.py validate hardware.json [--layout layout.json]`; `render hardware.json --layout layout.json --style style.json --output PREFIX` produces PREFIX.drawio, PREFIX.svg (via Desktop), PREFIX.png (via Desktop), PREFIX.hardware.json, PREFIX.layout.json, PREFIX.manifest.json. Support `--drawio PATH`, native-only validation/creation when export unavailable with explicit non-success for requested exports. Import edited drawio: `import EDITED.drawio --output PREFIX` extracts all native cells/styles/geometry and embedded original hardware metadata into a reviewable JSON, preserving unknown edits rather than silently erasing them. It need not guess new hardware facts from arbitrary foreign XML.

Diagram manifest records filenames, hardware and style hash, selected style name/revision if known, layout/validation issues. Unknown core fields fail instead of silently ignoring spelling errors; metadata may be explicit. `rules` guide Codex when composing the layout; the renderer does not execute prose. Hardware instance IDs remain stable during restyling.

Style library CLI is independent: scripts/library.py uses stdlib, root defaults to ~/.codex/hardware-block-diagrams; supports candidate registration, approval/rejection with provenance, learn creating immutable numbered revisions, list/show/default/rollback. Learned style format is the payload above. Learning extraction is performed by Codex vision, not claimed to be automatic image recognition by the script. Only approved samples can be learned; user originals/corrections have explicitly recorded user authorization. User corrections can be approved from the established automatic-feedback policy, never assistant-generated outputs. All filesystem identifiers must be safe slugs; writes atomic, source image snapshots locally copied, history preserved. Approval requests are handled by Codex conversation; CLI approval requires a nonempty evidence note. No network requests in library.py.

布局节点另可指定 `label_align: left|center|right`（默认 center），用于避开进入容器上沿的连线；例如容器标题使用 top + left。

可选 `tokens.edge_font_size` 设置连线文字字号（正数，默认 11）；与模块 `font_size` 独立。适用于大画布上连线标签太小的情况，无需导出后再改 XML。
