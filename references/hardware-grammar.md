# 硬件框图构图规则

## 组成视图：阵列、层级和共享资源

用户的 NPU 样本把 SoC 整体与单节点分别展示。可迁移的是：控制区在边缘、计算单元重复且对齐、共享资源跨越服务的计算范围、每个节点具有一致内部层级。不能把“四核”“L2”“VRU”自动添加到新设计。

1. 先列硬件层级树，再识别共享资源的服务集合。父容器标题留专用边带，不能压住子模块。
2. 对称或同构实例用相同尺寸和内部相对布局，实例名不同。若内部不同，真实表达差异。
3. 共享寄存器/缓存/NoC 可以画成跨列长条；有明确实际端点才添加连接。共享资源不应被误画为每个核各有一份。
4. 控制、计算、存储、互连可用类别色；同一图的图例一致。画多个层级视图时，标清对应实例或“单节点结构”。
5. 控制线少不代表不存在；根据图用途选择显示层级。主图保持关键互连，局部图可展开。

## 微架构视图：并行、汇聚和反馈

用户 CPU 样本明确分开 Front End、Execution Engine、Control Subsystem 和 Memory Subsystem。可迁移的是：并行功能单元横排、公共分发/写回跨列、回写绕外侧返回、取指与访存路径分开；不能从样本推定另一 CPU 的执行宽度或功能单元数量。

1. 先把功能分区排好，预留取指/访存与反馈通道，再摆放单元。
2. 并行单元共享水平或垂直基线；分发和汇聚条应覆盖服务范围。不要连接成 BRU→FPU→ALU 的虚假执行顺序。
3. 反馈线使用外侧通道和明确箭头。必要旁路/控制线细绘，不隐藏成泛化“循环”。
4. 宽箭头突出主通路；在适当处用细线表现次要控制，视觉权重不改变端点或方向。
5. 子模块只在所选抽象层级必要时展开。寄存器/FIFO可以用可编辑分格矩形，但不能捏造容量。

## 几何与审查

- 用户提供硬件事实；Codex 提供 absolute-coordinate layout。节点坐标最终转成父容器内相对坐标；所有连接保留 source/target。
- 为宽箭头预留至少其宽度加两侧留白的通道；实际查看拐角和端点，不机械照搬细线间距。
- 使用统一字号、可读中文字体；标签缺字、换行和对比度必须通过实际 PNG 检查。
- 先修错模块/错端点，再修分组、走线与文字，最后修颜色。不得用颜色装饰掩盖错误结构。
- 共享总线连接点和无连接交叉必须可分辨。父容器边界跨越是正常；穿越无关叶子模块不是正常。
- 两类视图可混合，但应明确主视图。空间不足先扩大画布或拆成整体/局部图，不无限缩小文字。

## 上游规则的取舍

采用 rockyco 的硬件类别、模块端点、显式布线路径和图像验收经验；不用其默认所有对象 `parent=1` 的扁平结构，不用脱离绑定的 detached edges，也不用菱形 MUX 作为普遍硬件约定。参考图重建采用 illustrator 的区域、重复结构、层次和视觉核对方法，不要求慢速播放。
